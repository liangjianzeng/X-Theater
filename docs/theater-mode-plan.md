- 制作团队**多模型混用是常态**（可灵+即梦+Vidu+海螺拼着用），流程靠剪映+手搓表格串联——**流程聚合层是真空白**；

### 1.4 差异化与护城河

1. **IP 资产库 = 数据壁垒**：角色卡/定妆照/三视图/音色/风格圣经/世界观随剧集沉淀——第二集开始，客户迁移=弃用全部 IP 资产，**用得越久锁得越深**；
2. **一致性可计量 = 定价权**：定妆照 embedding 相似度评分作为质量门+对客交付指标（「角色相似度 ≥0.85 才进视频阶段」），把行业最大痛点变成 SLA；
3. **混合算力 = 成本优势**：自建/包年 GPU 池跑量产档（1–4 元/分钟），API 只跑高价值镜头——比纯 API 工具便宜 60–90%，比单押自建弹性好；
4. **合规内建 = B 端准入证**：标识/审核/留痕在产品里内建，工作室客户无需自建合规能力；
5. **绑定平台扶持计划 = 获客通道**：对接快手 AI 创想剧场、抖音 AIGC 短剧招募、红果漫剧生态，工具成为「参赛标配」。

## 2. 产品体系（完整概念模型）

### 2.1 五级内容树

```
工作室 Studio（租户，席位+积分池）
 └─ 系列 Series（一部剧/IP：世界观、演员表、美术规范、音乐主题库——跨集沉淀）
     └─ 集 Episode（24 集×1.5 分钟的短剧；或 60s 单条广告）
         └─ 场次 Scene（戏剧单元：mood 标签 → 配乐/调色分段依据）
             └─ 镜头 Shot（生产原子：景别/机位/运动/时长/台词/出场角色→首帧→成片段）
```

- **Series 是 IP 沉淀容器**（角色/场景/风格/音乐主题全部挂 Series 级，跨集复用）；
- **Shot 是计费与调度原子**（每个 shot 有独立 job 链、成本归集、take 历史）；
- 支持竖屏 9:16 / 横屏 16:9 / 方形 1:1，**竖屏档为缺省**（短剧主战场）。

### 2.2 IP 资产体系（Series 级，Elements 深化）

| 资产 | 内容 | 一致性挂载点 | 生命周期 |
|---|---|---|---|
| **角色 Character** | 角色卡（姓名/年龄/外貌锁定字段/服装）+ **定妆照**（正面中性姿势锚点图）+ **三视图**（正/侧/背 turnaround）+ **音色卡**（TTS 音色 id + 3 句台词样本）+ LoRA（P2） | 定妆照 embedding = 该角色一切生成的比对基准 | draft → casting（定妆）→ locked → retired（季终） |
| **场景 Location** | 场景卡（描述/mood/时段）+ **定场照**（三张不同机位定场图） | 定场照做参考条件 + 卡字段注入 | draft → locked |
| **道具 Prop** | 描述 + 参考图 | 参考条件（复现信物类关键道具） | 同上 |
| **风格圣经 StyleBible** | 全局视觉规范：色板/光照/镜头/颗粒/负向词 + 画幅与平台规格 | 所有生图 prompt 的强制前缀 | Series 创建时锁定，改版需导演确认 |
| **世界观 Lore** | 大纲/人物关系/术语表 | 剧本解析的上下文 | 随剧本演进 |
| **音乐主题库** | Series 主题曲 + 分场 cue 规则（情绪→曲风映射） | 配乐生成的风格锚 | 随集扩充 |

### 2.3 八阶段生产流水线（核心）

每阶段：输入 → 产出 → **锁定门** → 回滚影响。锁定=冻结+版本标签；解锁需导演确认并记审计。

| # | 阶段 | 核心产出 | 锁定门（进入下一阶段的条件） | 回滚影响面 |
|---|---|---|---|---|
| 1 | **立项** | 系列圣经 v0（logline/世界观/集数/画幅/目标平台） | 大纲锁定 | 影响全部下游 |
| 2 | **剧本** | 分集剧本 → 场次树 → **台词表**（逐句：角色/内容/情绪/时长预估） | 场次结构冻结 | 改剧本→场次镜头重排（已生成镜头标记 stale） |
| 3 | **选角定妆** | 角色卡填写→批量出定妆候选→选定妆照→出三视图→绑定音色 | 演员表锁定 | 改角色→其所有镜头关键帧重出 |
| 4 | **美术设定** | 风格圣经+场景定场照+道具参考 | 美术包锁定 | 改美术→全局关键帧重出（成本最高的一次回滚，UI 强警示） |
| 5 | **分镜** | 镜头表（每镜：景别/机位/运动/时长/台词引用/出场角色）+ **动态分镜粗剪**（关键帧草稿图+scratch 配乐+台词 TTS 串成的 animatic，**近零成本验证节奏**） | 镜头表锁定 | 改分镜→重排关键帧 |
| 6 | **关键帧生产** | 每镜头首帧/尾帧（参考图条件生成）+ **一致性评分门**（相似度<阈值自动标记重出） | 帧锁定 | 改帧→该镜头视频重生成 |
| 7 | **动态生成** | 逐镜头 i2v/FLF 多 take；台词镜头：配音 TTS→口型驱动；**成本预算护栏**（超预算暂停待确认） | 成片段择优锁定 | 改成片段→重排合成 |
| 8 | **合成交付** | 时间线（转场/字幕/混音/调色）+ **合规标识自动嵌入**（§7）→ 成片 + 分镜 PDF（提案用）+ 工程包（交付/交接用）+ 平台交付规格（抖音/快手/红果/YouTube 竖屏预设） | 交付锁定 | —— |

**流水线纪律（产品铁律）**：
1. **先镜头表后生成**（业界共识，防算力浪费）；
2. **先粗剪后精做**：阶段 5 末的 animatic 让导演用近零成本确认节奏，阶段 6/7 只对锁定镜头批量开火；
3. **先锁画面后配乐**：配乐在阶段 7 按 locked cut 对齐（AI 音乐可无限重roll，视频重生成贵）；
4. **批量必先报价**：进入阶段 6/7 时按镜头数×单耗给出总预算与时长，导演确认才开跑。

### 2.6 版本与协作

- **Take 机制**：每镜头多次生成（含模型/seed/成本/一致性评分元数据），择优锁定；
- **版本树**：剧本/镜头表/美术包每次锁定成版本，任何下游可追溯到「当时的哪一版」；
- **角色分工**：导演（全权）/编剧（1-2 阶段）/美术（3-4）/后期（5-8 只读前段）/制片（只读+预算+看板）/管理员（席位计费）；
- **审阅流**：镜头卡级评论 + 待审清单（导演每天批一次，批完批量放行）；
- **看板（制片视角）**：集进度（八阶段漏斗）、预算消耗、GPU 队列、卡点告警。

### 2.7 模板与市场（Phase 3）

## 3. 一致性体系（定价权所在，单独成章）

| 层 | 手段 | 成本 | 依赖 | 阶段 |
|---|---|---|---|---|
| **L0 提示词锁定** | 风格圣经前缀 + 角色卡外貌字段逐字注入（preserve 机检）+ 场景卡注入 + seed 复用 | 0 | 无 | **P0** |
| **L1 参考图条件** | 定妆照/三视图/定场照作为参考条件出关键帧（图生图编辑模型，换构图不换脸） | 生图 +20–30% 时耗 | 参考图编辑模型（Qwen-Image-Edit 类 GGUF 档） | **P1** |
| **L2 身份微调** | 角色 LoRA/IP token 训练（每角色 20–50 张一致性图集，分钟级训练） | 每角色一次训练成本 | 训练服务 | **P2** |
| **L3 空间连续** | 首尾帧链（上一镜尾帧=下一镜首帧）+ 「过渡镜头」（A尾帧+B首帧生成衔接段） | 视频端点扩展 | FLF2V 模型档 | **P1** |
| **计量门** | 每张关键帧 vs 定妆照的 embedding 相似度评分：<阈值自动打回/换参考重出；评分随成片交付（一致性报告） | 可忽略 | 人脸/主体 embedding 模型 | **P1** |

业界共识：seed 只管复现、参考图才管一致性；免训练优先、LoRA 进阶。**把「跨集不崩」做成可计量交付物**（一致性报告 + 达标率 SLA）是避开 ¥1–4/5s 价格战的少数差异化空间。

## 4. 技术架构（商业化形态）

### 4.1 总体架构（端-云）

```
┌─ 端 ─────────────────────────────────────────────┐
│ Flutter 工作台（桌面/移动） + Web 工作台（浏览器）   │
│ 八阶段页面 · 故事板网格 · 时间线 · 看板            │
└──────────────┬───────────────────────────────────┘
               │ HTTPS/WSS（大产物走对象存储直传/直下）
┌─ 云 ─────────▼───────────────────────────────────┐
│ API Gateway（鉴权/限流/计费埋点）                  │
│ ├ 身份与工作区   ├ 项目与资产   ├ 剧本 Copilot     │
│ ├ 一致性服务     ├ 任务编排器   ├ GPU 调度器       │
│ ├ 模型服务网格   ├ 媒体处理     ├ 音频服务         │
│ ├ 审核服务       ├ 计量计费     ├ 通知/Webhook     │
│ └ 存储/CDN       └ 观测（成功率/成本/SLA）          │
└───────────────────────────────────────────────────┘
```

### 4.2 服务拆分

| 服务 | 职责 | 关键设计 |
|---|---|---|
| Gateway | 鉴权、限流、计费埋点 | 按 workspace 维度限流；积分扣减埋点在编排器统一做（防漏记） |
| 身份与工作区 | 实名、团队、席位、权限、审计日志 | 角色×阶段权限矩阵（§2.6）；审计留痕 ≥6 个月（合规要求） |
| 项目与资产 | 五级树、IP 资产库、版本、引用计数 | 元数据 PostgreSQL；产物 OSS 分层（热/冷）；引用计数防误删 |
| 剧本 Copilot | 大纲→分集→场次→镜头表的结构化解析与改稿 | LLM 结构化输出 + JSON 机检（模板+机检纪律，服务化）；多 LLM 路由 |
| 一致性服务 | 卡注入、参考图条件、LoRA 训练队列、相似度评分 | 定妆照 embedding 缓存；评分门是生成前的强制闸 |
| 任务编排器 | **持久化 job 账本 + DAG** | 每镜头一条 DAG（首帧→审核→评分→视频→审核→择优）；断点续跑、幂等重试、优先级、预算护栏；Episode 级批量编排（并行镜头数=算力余量） |
| GPU 调度器 | 三梯队算力路由（§4.4） | 显存互斥分区、竞价实例抢占迁移、闲时队列折扣 |
| 模型服务网格 | 模型注册/版本/量化/热载/推理 worker | 模型路由表（质量档×成本档）；A/B 评测基准集（内部一致性 benchmark） |
| 媒体处理 | 合成、转码、水印、隐式标识写入、字幕、封面 | FFmpeg 集群（CPU 池，便宜）；标识在合成层强制（用户不可绕过） |
| 音频服务 | 配乐 cue、TTS 音色、口型驱动 | 音色卡与角色绑定；TTS 结果缓存复用 |
| 审核服务 | prompt 机审→产物抽帧机审→人工复审队列→处置留痕 | §7；审核通过是合成阶段的强制依赖 |
| 计量计费 | 积分账本、按 shot 成本归集、订阅/发票 | 每 job 记 GPU 秒×费率 或 API 消耗，成本可穿透到每个镜头 |

### 4.3 任务编排（商业级核心，展开）

单镜头 DAG：

```
shot(draft) → kf.first(生图) → mod(机审) → sim(一致性评分门)
   ├─ pass → kf.lock（人工/自动锁定）
   └─ fail → 自动换参考/换 seed 重出（≤N 次）→ 升人工
kf.lock → tts(若台词) → video.i2v → mod → take 入库（元数据：模型/seed/时长/成本）
take.pick(择优锁定) → compose（Episode 级：时间线+转场+音轨+标识）→ export → 交付
```

- **断点续跑**：账本落库，worker 崩溃/服务重启从最近成功节点续跑；镜头级幂等键防重复扣费；
- **预算护栏**：Episode 批量前预估总成本，超预算暂停待制片确认；
- **优先级**：付费档 > 免费档；闲时（错峰）积分折扣（学 Vidu，把夜间算力卖出去）。

### 4.4 算力体系（三梯队混合，成本优势的来源）

| 梯队 | 构成 | 承载 | 单位成本（720p） |
|---|---|---|---|
| T1 自部署 GPU 池（**二期商业化形态**） | 4090 租赁池/自购，蒸馏优化量产档（Wan 5B 级、LTX-2.5 快档）；**一期＝自有 5060 Ti（开发）＋DGX Spark（验收/自生产，H3 nvfp4 直调）** | **80% 产量**（量产档、重roll、草稿） | **1–4 元/分钟**（前提：蒸馏档＋利用率 ≥55–65%） |
| T2 云 GPU 弹性（**二期接入**） | AutoDL/RunPod/fal 竞价与按秒实例 | 峰值溢出＋公测 SLA 主力 | 2–25 元/分钟 |
| T3 商用 API（**二期商业化策略**） | 可灵/Vidu/海螺/Seedance（全部已备案底座） | 高价值镜头精修、质量档、BYOK；一期仅 UI 槽位+接口预留 | 15–90 元/分钟（旗舰档现价） |

调度策略：模型路由表（镜头标 quality=tier1/tier2/tier3）+ 失败降级链 + 竞价实例被抢占时任务迁移账本续跑。**API 定位（2026-11-20 发起人确认）：平台商用运营策略、最后接入项——质量补充＋BYOK 轨道，二期起生效；一期集中力量自部署能力，路由表仅 schema/槽位预留**。

### 4.5 存储与分发

OSS 分层：产物热层（0.12 元/GB/月）→ 30 天未访问降冷层（0.033 元/GB/月）；成片 CDN 0.24 元/GB（观看 1 分钟 720p ≈ 0.024 元）；工程文件（剧本/分镜表/JSON）走数据库+快照。

### 4.6 可观测性与 SLA

- 任务成功率/时长/成本 per job、per 模型、per 客户——ClickHouse 聚合；
- 模型质量回归：内部一致性 benchmark 集（固定角色×50 镜头），每次换模型版本跑回归；
- SLA：工作室档承诺排队 P95 < 10 分钟、批量完成时间可预估展示。

## 5. 数据模型详设

### 5.1 核心实体（ER 简图）

```
Studio 1─* User(席位)        Studio 1─* Series
Series 1─* Episode           Series 1─* Element(Character/Location/Prop/StyleBible/Lore)
Episode 1─* Scene            Scene 1─* Shot
Shot 1─* Take                Shot/Element 1─* AssetRef → Asset(产物文件+元数据)
Shot 1─* Job(DAG 节点)       Job 1─* BillingEvent
Shot/Scene/Episode *─* ReviewRecord(审阅/锁定/解锁审计)
```

### 5.2 关键 schema（SQL 视角，关键字段）

```sql
-- 系列（IP 容器）
series(id, studio_id, title, logline, aspect '9:16', platform_spec jsonb,
       style_bible jsonb, lore jsonb, status, version, created_at)

-- 角色（一致性核心）
element_character(id, series_id, name, appearance_locked text,   -- 逐字注入
       outfit text, voice_card jsonb, anchor_asset_id,           -- 定妆照
       turnaround_asset_ids[], lora_model_id,                    -- P2
       face_embedding vector, status draft|casting|locked|retired,
       similarity_threshold real DEFAULT 0.85)

-- 场次（音乐/调色分段单元）
scene(id, episode_id, title, synopsis, mood_tags[], seq)

-- 镜头（生产原子）
shot(id, scene_id, slug, cast_ids[], location_id, prop_ids[],
     shot_size, camera_motion, duration_sec, dialogue_id,
     first_frame_prompt text,        -- 组装后的完整提示词（含圣经+卡注入）
     first_frame_asset_id, end_frame_asset_id,
     pick_take_id, status,           -- 状态机见 5.3
     cost_accumulated numeric,       -- 该镜头累计成本（穿透计费）
     consistency_score real)         -- 最近一次评分

-- take（同一镜头多次生成）
take(id, shot_id, asset_id, model_route, seed, gen_params jsonb,
     similarity_score real, cost numeric, picked bool, created_at)

-- job（DAG 节点，持久化账本）
job(id, shot_id, kind kf|mod|sim|tts|video|compose|export, state,
     depends_on job_id[], payload jsonb, worker_id, attempts,
     cost_estimate, started_at, finished_at, idempotency_key UNIQUE)

-- billing_event（计量，不可变追加）
billing_event(id, studio_id, job_id, meter gpu_sec|api_call|storage_gb|cdn_gb,
     quantity, unit_cost, created_at)
```

### 5.3 状态机

```
Shot: draft → keyframeReady → keyframeLocked → generating
      → clipReady → clipLocked → composed → delivered
      （任一步可 failed → 重试/升人工；上游锁定物变更 → stale，下游全部重开）
Episode: outlining → scripting → casting → arting → boarding
         → kf_batch → gen_batch → composing → delivered
ReviewRecord: 任何 lock/unlock/batch-approve 记录操作者与版本（合规留痕）
```

## 8. 实施路线图（孵化路径）

> **⚠ 口径存档注记（2026-11-20 终审）**：本节为 v2.0 期孵化路径原文，**凡与总文档 §7／一期计划冲突处以彼为准**：一期＝完全自部署（无「API 为主＋包年 4090」）、种子 8±2 家（非 10–20）、利用率目标 ≥55–65%（非 ≥50%）、GPU 采购按租赁池口径（新卡 ¥23k+/张）、Phase 3 海外版以 H3 区域排除（EU/UK/KR/US）为前置、**生图先行纪律**（先跑通生图再上视频链路）适用全部 Phase。

### Phase 0 · 本地原型（4–6 周，现有开发机，0 新增硬件）

**目标**：以本地原型（独立代码库，仅复用本文数据模型与合规设计）验证「八阶段流水线」的产品假设与一致性下限。**（注：本 Phase 0 已被一期自部署方案整体替代，见总文档 §7 与 [一期计划](theater-phase1-plan.md)，此处仅存档）**
**范围**：TheaterDoc 数据模型（五级树的最小集：Series/Episode/Scene/Shot）+ 剧本解析（LLM→镜头表 JSON 机检）+ 角色卡/风格圣经注入 + 分镜网格 + 批量首帧 + 逐镜头 i2v + concat 成片；一致性走 L0（提示词锁定）+ 人工审阅。
**验收**：一段话输入 → 8–12 镜头、带配乐、竖屏 9:16、1 分钟短片，全程零手搓文件操作；**跨镜头角色辨识度「可用」的主观判定 + 相似度评分脚本建立**。
**复用范围（独立产品裁决 2026-11-20）**：仅复用本文的数据模型与合规设计；工程全部在独立代码库新起，不复用任何既有产品的代码/组件/测试基建。

### Phase 1 · 云端私测（2–3 个月，2–3 人）

**目标**：10–20 家种子工作室（AI 漫剧产能型）真实生产，验证付费意愿与真实单耗。
**范围**：多租户最小集（鉴权/席位/项目资产/持久化 job 账本）+ 三梯队算力起步（API 为主+1–2 张包年 4090）+ 一致性 L1（参考图条件+评分门）+ 首尾帧链 + 配音 TTS + 显式/隐式标识 + 机审接入。**（2026-11-20 修订：一期以自有 5060 Ti＋DGX Spark 自部署做验收与自生产、自部署模型为主力，邀请制内测不报价；商业 API/托管弹性作为 SLA 与质量档随二期公测引入，备案义务在公测前 6–8 个月启动）**
**预算**：云与 API 约 3000–8000 元/月 + 人力。
**验收**：种子客户周均交付 ≥3 分钟成片/家；周留存 ≥60%；报价意愿访谈定价假设校准。

### Phase 2 · 商业公测（3–6 个月，4–6 人）

**范围**：自建 GPU 池（8–16×4090 起步，约 12–24 万一次性或包月租赁）+ 调度器利用率优化 + 计费/发票/席位协作 + 口型驱动 + 一致性 L2（角色 LoRA）+ 平台扶持计划合作（快手 AI 创想剧场/抖音 AIGC 计划）+ 备案收尾。
**验收**：付费转化 ≥15%（私测池）、月产分钟数 >2000、单分钟交付成本 ≤4 元、GPU 利用率 ≥50%。

### Phase 3 · 生态与规模化（6–12 个月）

API 开放（pipeline-as-API）、私有化交付（复用本地栈基因，制片厂档）、模板/LoRA 市场、海外版（海外部署、英文工作台、合规差异化）。

## 9. 风险清单与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 一致性达不到「跨集不崩」的体验线 | 高 | 四层体系分层兜底；评分门早暴露；多模型路由（哪家稳用哪家）；L2 LoRA 是最终解，Phase 2 前完成 |
| API 价格战持续下探，裸生成无利润 | 高 | 从 Day 1 不卖裸生成卖产线；自建 T1 摊薄成本；一致性 SLA 是唯一溢价空间 |
| 国内 AI 短剧产能过剩、平台政策波动 | 中 | 出海版本地化；绑定平台扶持计划成「参赛基础设施」而非内容方 |
| 竞品（可灵/即梦）补齐流程层 | 中 | 我们的优势在垂直深度（竖屏/台词表/口型/分账生态/合规内建）与 IP 沉淀迁移成本；保持月度迭代节奏 |
| GPU 利用率不足导致成本失控 | 中 | 调度器是 P2 一级工程项；闲时折扣；API 兜底弹性 |
| 合规处罚 | 中 | API 起步轻路径；标识/审核/留痕产品内建；每季度合规复审 |
| 单人研发节奏 vs 路线图 | 现实 | P0 本地原型与 P1 私测可串行为一个人节奏；P2 起建议 2 人以上（调度器+计费+合规三线并行） |
| **漫剧专项治理＋平台真人倾斜**（P0 客群恰为被治理供给方） | 高（评审新增） | 题材白名单；真人向/出海预案；种子客户选已过盈亏线「幸存者」（DataEye 2026H1 仅 1.3%） |
| **画布红海＋平台官方工具免费化**（泡漫/巨日禄/即梦+小云雀/快手自研；模型厂商下场做流程层） | 高（评审新增） | 五维交集差异化（审计级一致性/合规内建/私有化）；多平台中立对冲；该假设列最高优先级持续验证 |
| **自部署吞吐不达量产线**（Spark×1 月产能 150–400 分钟） | 高（评审新增） | 一期不承诺 SLA（验收/自生产语义）＋夜间闲时队列；二期托管弹性为 SLA 主力（P95 gate：≥2 节点/并发 ≥8） |

## 0. 评审结论（TL;DR）

| 视角 | 评分 | 一句话结论 |
|---|---|---|
| 市场与商业 | **5/10** | 主干数据可溯源、方向可救；但「工具层空位」已被 2026-11 竞品现实证伪，单位经济数学不闭合 |
| 用户与体验 | **7/10** | 方法论强（样片枢纽/报价卡/语言表是真功夫）；但付费主力 S4 的控制类功能被排期背叛、计费语义黑箱、若干机制未压测 |
| 运营 | **3/10** | 按「产品上线」写的，不是按「平台有人伺候」写的：机审 P0 就有、复审工作台/告警/计费举证全在 P1 |
| 开发与架构 | **6/10** | 三份 ADR 方向性判断正确（可给 8 分）；P0 层坏：算力口径四处矛盾、排期缺口 60–150%、数据模型缺资产表与对账结构 |

**总评：方向成立、纪律罕见地扎实，建议「带条件通过」评审。** 承重墙有四处必须先重新浇筑，否则 P0 期内必炸或商业模型不闭合：

1. **算力口径四处矛盾 + 现实硬件兑现不了自建档**（T1/T5）——评审会第一裁决项；
2. **单位经济不闭合**（T2）——定价折合价 ≈ 盈亏平衡线，重拍倍数与 API 份额两个决定性参数全案未建模；
3. **数据模型「钱与血缘」缺口**（T4）——asset/账本结构缺失会在 P0 第 3–4 周以推翻 schema 的形式兑现；
4. **运营与合规闭环缺失**（T7/T8）——复审队列、计费举证、备案资格（经营性 ICP 许可、生成式 AI 服务备案）无人无钱无流程。

**建议的评审通过条件（三条）：**
- ① 评审会前：完成 T1 算力口径、T2 定价结构、T3 市场定位三场书面裁决并回写全部文档；修正合规表述（「属地登记」→备案框架）、删除无出处数字（「处罚 200+ 起/500 万」等）、竞品表按 2026-11 现实重写；
- ② 开发启动前：数据模型勘误（§5 勘误清单）落进 schema；P0 排期改为 **12–16 周双里程碑**并按砍单清单执行；验收线重写（P95<25min 移出 P0）；「运营最小后台 + 计费举证三件套」进 P0；模型准入白名单（Apache/MIT 名单 + H3/LTX 许可条款台账 + 备案义务日历）建立；
- ③ P1 准入闸：实测「生成分钟/交付分钟倍数」与「自建/托管/成本占比」两个定价参数；生成式 AI 服务备案启动（预留 6 个月）；种子客户目标与运营容量对齐（8±2 家深度共建，或 +1 名 CS + 复审外包）。

## 1. 横向关键问题（评审会裁决清单 Top 10）

> 编号 T1–T10；括号内为支撑发现编号，详见 §2–§6 各视角清单。

### T1 [P0] 算力口径必须先裁决：四处矛盾 + 现实硬件只允许一个答案
（F-D-01/02/30、F-M-04、硬件专项 D2/D3）

同一评审包里 P0 执行层有四个互斥答案：[U] §1「100% API 无本地推理」；ADR-001 §6「自托管 2–4 卡 ComfyUI worker」；总文档 §10-Q8「建议全托管起步」；发起人现实硬件「5060 Ti×1 开发 + DGX Spark×1 生产」。且 §7.1「云+API 2000–5000 元/月」连自建 2–4 卡（仅租用即 ¥2000–6000/月）都覆盖不了，硬件资本支出（5060 Ti ≈¥4.6–5.8k、Spark ≈¥3.4 万）完全未入预算表。

**裁决建议（写回 ADR-001 §6、总文档 §7.1，[U] §1 加注「已被 ADR-001 修订」）：**
- **P0 执行底座 = 托管 ComfyUI 双供应商**（fal / RunPod 按秒，min-worker 对冲冷启动；注意 Comfy Deploy 现无 4090/A100 档，卡型假设需更新）+ **商业 API 质量档**（已备案底座，兼起步期合规底座）；
- **5060 Ti = 模板熔炉**（全部开发实现与前期调测；LTX-2.5 仅 distilled+GGUF UD-Q4_K_XL 档可全入显存，见 T5）；
- **DGX Spark = 验收/审计复跑/夜间闲时/长尾容量节点 + LLM 类负载宿主**，**不是量产主力、不作任何 SLA 依据**；
- **量产成本档 = 4090 租赁池（蒸馏档）**，P1 末按真实利用率决定是否兑现（定价核查：优化档租赁价下 1.0–3.5 元/分钟成立，Spark 单独承担为 3–9 元/分钟）；
- worker_type 四路可换的不变式保留，Spark 故障 watchdog 自动摘流后自动档无损。
- **合规联动**：P0/P1 对外提供生成服务一律走已备案 API（可灵/火山/MiniMax API）；自建/托管开源模型定位为内部管线与质量可接受档，应用侧备案（见 T8）在公测开放注册前完成。

### T2 [P0] 单位经济不闭合：盈亏平衡恰好压在定价折合价上
（F-M-02、定价核查、F-D-03、F-U-02）

- **盈亏表（工作室档 ¥699/180min，折合 ¥3.88/分钟，全含口径）**：平均成本 1.5 元/分 → 毛利 61%；3.0 → 23%；**3.88 → 0%（盈亏平衡）**；4.5（方案成本上限/Spark 常态）→ −16%。制片厂档 ¥3/分钟、溢出价 ¥3–4/分钟低于自报混合成本区间（3–8 元）多数取值——结构性负毛利档位。
- **决定性参数二：API 混入率**。量产档内每混入 1 分钟 25 元级 API，平均成本 +0.24 元/分钟；混合结构 T1@1.5+T3@25 时，精修占比 5%→毛利 31%、**10%→1%、15%→−30%**。「API 份额 ≤5–8%」必须做成积分账本里的**硬路由约束**（精修一律走独立精修包），不能是默认行为。
- **决定性参数一：重拍倍数（生成分钟/交付分钟）全案未建模**。四位评审给的估计区间 1.3–2×（开发/定价）到 2–4×（市场）；方案自己的机制（多 take 择优、一致性门自动重出 ≤2 次、重拍 chips、超 20% 才暂停）意味着这恰是最敏感的参数。冻结价目前必须实测入库。
- **§6.1 表两处口径错误**：「1.5–3 min GPU 时/分钟」实为**26–72 分钟 GPU 时/产出分钟**（低估约 20 倍；括号内「60–150s/h」反而与 lightx2v 实测吻合）；「API 价格地板 ¥2–4/5s」已过期——真地板 **¥0.5–1.25/5s**（Vidu q2-pro-fast/错峰、Seedance 2.0 mini）。BYOK/精修包报价页若按 2–4 元锚定，客户拿官方价一页纸即击穿。
- 规模拐点从「月产>2000 分钟且利用率>40%」上调为「**利用率 ≥55–65% 且月产 ≥1500 分钟**」；P2 预算「12–24 万买 8–16 张 4090」按现卡价（新卡 ¥23k+/张、AutoDL 常抢不到）只够 5–10 张，需按二手/租赁年包重列。
- 定价动作建议：工作室档改 **¥699/120min 或 ¥899/180min**；溢出价 ≥ 边际成本×1.3；BYOK 从「进阶附庸」升为一等公民并单列订阅费，做「BYOK 订阅 vs 积分价」毛利当量对照表。

### T3 [P0] 市场「工具层空位」已被证伪：画布/工作台是红海，定位需重写
（F-M-01/05/08/09/14）

- 娱乐资本论 2025-10 已做「**10 家视频画布横评**」：AniShort、巨日禄、LibTV、纳逗 Pro、OiiOii、Seko、ShotLab、TapNow、万兴剧厂、小云雀——品类成熟到第三方同题横评的程度；方案竞品表 10 家只出现纳逗 Pro 一家且定性错误。
- 上市公司已下场：掌阅（603533）2026-02 发布 AI 漫剧一站式平台「泡漫」，主打「全流程工具链 + IP + 分发」，正压在方案最自信的 IP 资产护城河上；万兴剧厂、巨日禄（漫剧圈多年主力）、知漫剧（系统级角色库）各占一角。
- 平台「工具+流量+钱」三件套：即梦 Seedance 2.0 经小云雀 APP 免费体验、豆包+即梦+可灵「30 分钟出一集」教程公开流传；快手 8 亿分账+2 亿现金+10 亿流量池配可灵；红果 AI 系列短剧 15 天 60 亿播放。模型层还在免费化工具层卖点（Vidu Q2「一致性焊死」）。
- P0 客群正处三重挤压：广电 2025-11 起不良动画微短剧**专项治理**（漫剧上线量 6567→2441 部/月）+ 各平台真人剧专区倾斜；外包价塌方至 **¥200/2 分钟**（一年前约 1 万）；2026H1 抖音 AI 剧上新 22.19 万部中过盈亏参考线仅 1.3%。「工具费占收入<5%」的付费确定性论证需重做。
- **定位重写**：「空位」收缩为**五维交集**（多模型无感路由＋锁定门审计留痕＋交付级一致性评分报告＋平台交付预设＋合规内建）——「很多人做了 60 分的全流程，没人做 B 端可审计的那 40 分」。差异化每条须回答「泡漫/巨日禄已有，我们赢在哪」；一致性 SLA 要绑「跨集 IP 资产 + 对平台/广告主可审计的交付报告」这类模型层给不出的东西，并写成对赌/返点合同条款。
- 风险登记册新增「漫剧专项治理与真人倾斜（高）」；「平台政策波动」由中升**高**；「可灵/即梦 12 个月内发布工作室级流程层」列为最高优先级外部假设并给预案。种子客户名单改造：≥3 家**已过盈亏线的头部幸存者**（签带价位 LOI）+1 家出海团队+1 家品牌/MCN。

### T4 [P0] 数据模型「钱与血缘」缺口：第 3–4 周推翻 schema 级
（F-D-19/20/21/22/23 + 勘误清单 §5）

- **asset 表整体缺失**：anchor_asset_id、take.asset_id 等引用遍全文而 asset 无处定义；voice_card 把资产 id 藏进 jsonb 导致 lineage 不可计数。补 `asset` + `asset_ref`（引用计数=派生查询禁缓存列，删除保护=存在活跃引用即拒删+tombstone+异步 GC）。
- **job/billing 撑不起「预算护栏+对账+幂等」**：job 只有 shot_id（compose/export 集级无处挂）、幂等键全局 UNIQUE（跨租户撞键）、billing_event 无方向/状态/attempt/钱包维度、失败 attempt 成本无归属。「断点续跑、幂等不重复扣费」两条 NFR 目前只是口号——**双分录钱包 + 对账不变量（夜间 property test + 违约熔断批量入口）是它的可验证形式**。
- take 择优双写真值源（take.picked 与 shot.pick_take_id）→ partial unique index 单一事实源；stale 只有语义没有机制 → 下游物化来源版本快照 + junction 表反查；shot 无乐观锁 → version CAS + 编排器单写者。
- **embedding 阈值 0.85 对动漫画风基本不可用**（人脸 embedding 对 2D 脸检测率会崩，且 cosine 值跨 embedding 版本/路由不可比）→ 删默认值，加 `style_domain(2d|real|hybrid) × model_route × embedding_version` 标定表；2D 档改用 DINOv2/CLIP 主体级比对。评测集（5 画风×8 角色×10 镜头+50 漂移例）目前无人认领——发起人+2 家种子共建。

### T5 [P0] 本地硬件与模型定位改写（专项调研结论）
（硬件专项、F-D-30/31/32/33、定价核查 G 组）

**5060 Ti 16G（开发调试，LTX-2.5 主跑）：**
- 唯一可全入显存档 = **distilled + GGUF UD-Q4_K_XL（14.0GB）**。注意：unsloth 实测 UD-Q4_K_XL 明显优于 Q4_K_M、与 Q5_K_M 持平——发起人「Q4_K_M 优先」应改为 **UD-Q4_K_XL**；官方 int8（21.5GB）/nvfp4（18.7GB）/fp8 全部超 16G。
- 「质量优先」在 16G 上的正确表达是「**distilled 步数档优先于精度档**」；FastH3 在 16G 只能 Trim 档（4090@16G 限实测 768p≈140s）；相对 4090 耗时 ×1.6–2.2。
- **装 Ubuntu/WSL2**：natten 仅 Linux、FlashAttention-4 消费级 Blackwell 有已知问题、blackwell_dsl 数据中心限定——Windows 裸跑的基准数据不作数。5060 Ti 是调通机不是基准机。
- 不模拟 worker 池：单卡「一模型一 worker」是伪需求，显存互斥显式卸载串行；OOM 铁律=同参数不同机重试、重试即降档梯子、OOM 后强制重启进程。
- 四元组+CI 回归在 1 卡上会堵死开发：**P0 降级为容器镜像 digest 锁定 + nightly 5-shot 冒烟**；完整 CI 基准集列 P1 且必须在 Spark/托管上跑（生产同构）。comfy-api-proxy 仅 4 个月大/14★，生产依赖需自带自写 `/prompt`+WS 适配层兜底任务卡；锁定项扩为五元组（+proxy commit+镜像 digest）。

**DGX Spark（初步生产，MiniMax-H3 主跑）：**
- **SLA 语义不可行、批处理语义勉强可行**：FastVideo 官方实测 FastH3 NVFP4 768p/5s = **340s/镜**（4090 的 2.5 倍、RTX PRO 6000 的 9 倍慢），12 镜 ≈ 68 分钟，超 P95<25min 目标 2.7 倍；月产能 150–400 分钟，只够 1–2 家工作室档。定位按 T1：验收/夜批/降级/长尾。
- 量化：**nvfp4 优先于 int8**（GB10 原生 FP4，FastH3 Spark 版即 NVFP4 校准档；纯 int8 慢 1.5–2×）；int8 留给 VAE/TAE 与注意力敏感层。发起人「int8 或 nvfp4」口径成立，取 nvfp4。
- **H3 不进 ComfyUI 主线**（nvfp4 kernel 覆盖不全），走 FastVideo 直调——「毕业机制」顺序因此反转：首个真实毕业 = H3/FastVideo on Spark，P1「生图直调毕业」降级为回归参照。FastVideo/ltx-kernels 纳入 vendor fork 白名单（单点依赖风险）；sm_121 kernel 需自编译，锁 NGC 容器为唯一生产运行时；**H3-Context-IR 为托管件**，自托管需按官方 skills 仓库本地复刻并入四元组，否则自建档质量与 API 档不可比、一致性门误判。
- 样片 SLA（12 镜<3min）本身不含视频生成，达标无压力；但分镜图必须前置生成/缓存。

**辅助模型商用白名单（逐仓核验）：** 生图 Qwen-Image-Edit-2511（Apache，16G 走 GGUF Q4）+ Z-Image-Turbo；i2v 成本档 Wan2.2-TI2V-5B（Apache 干净，且已是**全案唯一无营收门槛的主力候选**）；TTS CosyVoice2（Apache）；配乐 ACE-Step 1.5（MIT）。**禁入商用链路**：FLUX.1-dev/Kontext 全系（non-commercial）、F5-TTS（CC-BY-NC）、MiniMax M2.7（开源权重非商业）、IndexTTS-2（license 未标注，法务核验前不用）；CogVideoX 须先注册取免费商用许可且月访问 ≤100 万；LatentSync 仓库/HF 卡两处 license 不一致，以部署包内文本为准留存快照。另：Wan 已发布 3.0，技术栈基准落后一代，Q4 图像/视频基线选型时一并复审。

### T6 [P0] 模型许可 × 产品语言纪律 × 出海，三处正面冲突
（硬件专项红线、合规核查 B 组、F-D-06）

- **MiniMax-H3**（已核 HF LICENSE 原文）：① 年营收 >$20M 须事先书面授权；② **商用产品 UI 须显著展示「MiniMax H3」**（分发另加 Powered by + NOTICE）——与总文档 §1.4/[U] §7「界面禁技术词、剧组拟人包装」**正面冲突**，不能藏不能改名；③ **开放权重地域排除 EU/UK/KR/US**（API 不受限、可申请授权）——P3 出海版用 H3 必须先拿区域授权，或出海线换 Wan/LTX-Apache 底座；④ 托管服务须内置防滥用+举报机制（直接约束 SaaS 形态）；⑤ **禁止用 H3 输出训练其他模型**——任何「用 H3/LTX 产物微调自有模型」的实验先过法务。FastH3 蒸馏权重同受全部义务（Model Derivatives 条款）。Comfy 教程页「本地生成物商用需购 MiniMax 许可」与 HF 许可存在表面冲突，需书面澄清。
  **UI 标注处置建议**：把「MiniMax H3」定性为**品牌署名而非技术参数**——成片片尾卡/登录页页脚/关于页呈现，避开工作界面；P1 前取得法务书面意见。营收阈值监控+授权预算线从 P3 提前至 P1（0.5 PD 台账任务）。

### T7 [P0] 运营闭环缺失：机审 P0 就有，复审工作台/告警/计费举证全在 P1
（F-O-01/02/03/05/09/11/12/13/15、容量测算）

- **「机审 P0、复审工作台 P1」断层**：审核通过是合成强制依赖（[P] §4.2），复审积压=导出停摆=种子客户周更断更，而短剧周更高峰恰在周末、团队 1–2 人。**P0 补「运营最小后台」包（3–5 天）：复审工作台（列表+播放+过/杀+理由）+ 处置动作（下架/封禁/申诉）+ 最小告警面板**。
- **复审产能外包**（云厂商人工审核 BPO 约 ¥2–6k/月，计入 P1 预算）+ 架构裁决「机审过即可临时导出（隐式标识+内容 ID 全留痕）→ 异步人工复审 → 可撤回（CDN 刷新+下架协议+客户通知）」，把复审从导出硬前置改为交付后异步闸（机审服务不可用时 fail-closed）。
- **词库无 owner、参考图通道裸奔**：FR-107 允许上传「真人照片/竞品画风」——prompt 黑名单管不到「明星照片拖进人物槽」。词库版本化+2 小时热更通道+红队测试；**参考图上传即过图像机审+人脸比对**（同时是 F-D-15 注入防护与 F-O-18 个保义务的交汇点）。误杀申诉通道与处置同期上线（P0 最小版）。
- **计费争议举证三件套提 P0**：review_record（lock/unlock/开机确认快照）+ job 加 `initiated_by: user|system` + **系统发起消耗（一致性重出/降级/重试）默认平台承担并在成本穿透页明示**。「用户说这一镜我没让它跑」是必然发生的第一场对质，举证链断裂送出的每个积分都会污染 P1 定价校准。
- 免费转收费过渡（共建协议模板：实名去重按营业执照、反馈义务、案例授权；免费期「影子记账」照常入 billing_event 否则定价校准无数据源）；账户级余额预警+停服策略（FR-606 只是项目级护栏）；供应商出站限流/涨价传导条款/BYOK 预检与失败归因。

- 「绑定平台扶持计划」从 P0 卖点降档为 **P2 BD 项目**（补贴对象是出品方非工具商，重 BD 重费用且政策多变），增长改走「种子案例→扶持计划内产出署名→反哺获客」的低依赖打法。

### T8 [P0] 合规基线修正：备案表述、缺失资格、不可证实数字
（合规核查 A 组、F-O-16/17、F-M-13）

- **「调用已备案底座→只需属地登记」表述错误**：法规中不存在这个独立豁免通道；用已备案底座只是简化备案材料，**不豁免应用侧备案本身**。正确框架：生成式 AI 服务备案（属地报送）+ 算法备案（涉深度合成）+ 安全评估（舆论属性），**按 6 个月预留**（方案「1–6 个月」偏乐观）。B 端豁免（办法第二条「未向公众提供」）有文字依据但无官方口径，**不可依赖**——尤其 SaaS 对不特定付费客户服务。P0 走邀请制内测（不开放自助注册）可辩护；公测开放注册前备案就绪或明确风险决策。
- **付费 SaaS 缺「经营性 ICP 许可证（增值电信业务经营许可）」**——方案只写了 ICP 备案；省通管局法定 60 日、实际 2–4 个月，支付/云/上架资质审核都会卡。等保三级是 B 端采购现实门槛（测评排期 1–3 个月）。两者加入 P1/P2 里程碑。
- **「标识办法施行后处罚 200+ 起、单笔最高超 500 万」查无官方出处**——2025-11-25 集中查处通报属实（约谈/限期改正/下架），但计数与金额未见于官方渠道，删除或注明媒体来源，否则客户/投资尽调当场打回。
- GB 45438-2025 为强制性国标但公开系统不免费公开全文——**上线前购买标准原文做字段级符合性测试报告**（元数据字段：内容属性/服务者编码/内容编号；显式标识位置/时长/字号参数）。「水印=强制」表述不准确：义务本体是元数据，水印是鼓励项（做成强制是保守正确，但别写成国标义务）。去显式标识需协议约定+**留存提供对象信息日志 ≥6 个月**（方案漏了后半句）。
- 持续义务无 owner 无日历：建**合规义务日历**（备案→年度评估→功能变更重评→报告，每项有日期/owner/证据物）；留存清单五类化（prompt、产物原件、审核记录、处置记录、实名与协议凭证）+按用户/时间/内容 ID 可检索+调证响应 ≤24h；被举报处置 SLA；违法内容「处置+**向主管部门报告**」（办法第十四条，方案只写了留痕）。
- **发票/对公/合同排期错配**：发票在 [P] 排 P2，但 P1 就要向种子客户收钱——P1 补「对公认证+开票（可外包财税 SaaS）+内容安全承诺函」三件套；B 端认证做主体级（营业执照核验），兼作防白嫖与义务主体界定。
- 个保：真人照片进参考图槽位=敏感个人信息处理，需单独同意+PIA；竞品画风/商品图上传需「通知-删除」受理通道。

### T10 [P0] 用户侧五个 P0：兑现性、计费语义、验收时序、人工兜底、移动误操作

- **失败镜人工兜底（P1 必做）**：镜头级人工资产注入（上传视频/图片替代 take 参与合成、标 manual 不进评分正常计费）——AI 搞不定的 10% 决定整部剧交付，是产线与玩具的分界。
- **验收时序倒挂**：关键帧阶段「评分门自动过」+ 逐镜审片/P1 手动路由/P2 时间线 = 最贵的钱花完才让 S4 导演看。导演台加「关键帧人审门」开关（**工作室档默认开**）；验收卡内嵌逐镜九宫格快审。
- 移动审片：花钱动作不能是滑动——通过/重拍改大按钮+确认（弹预计成本/时长），保留上滑=下一镜原始语义，补撤销/批量待审篮/@同事/弱网预载/触达通知。
- **双表面 P0 裁决**：P0 卡片流为唯一写路径、工作台只读（否则每个 FR 隐性 ×2，1–2 人做不完两个产品）。
